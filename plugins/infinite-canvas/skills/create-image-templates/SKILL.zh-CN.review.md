# 图像模板制作 Skill 中文核验稿

> 本文件用于人工核验，整理自当前
> [`SKILL.md`](SKILL.md) 与
> [`references/prompt-and-qa.md`](references/prompt-and-qa.md)。
> 实际执行仍以英文源文件为准。本文件不参与 Skill 加载。

## 1. Skill 目标

针对参考文档、飞书文档或 Wiki、截图以及用户提供的图片，在 Infinite Canvas
中为每张参考图建立一套可复用的图像模板工作流。

工作流必须遵守严格的付费样片验收门禁：

1. 完整读取并分析参考资料。
2. 使用 Soul 2.0 生成独立的模特人物素材。
3. 反向整理可复用的模板效果提示词。
4. 使用付费模型生成 `2:3` 样片并进行参考图对比。
5. 如确有必要，自动生成一次修正版 V2。
6. 暂停并等待用户验收。
7. 只有在用户明确验收通过后，才生成 Free/boogui2i 对照版本。

使用画布工具前，必须先加载并遵循
`../operate-infinite-canvas/SKILL.md`，包括先读后写、模型目录读取、布局、执行和
完成报告规则。撰写提示词或审核生成图前，必须阅读
`references/prompt-and-qa.md`。

## 2. 阶段一：读取并索引参考资料

### 2.1 飞书文档读取

当输入为飞书 `/docx/` 或 `/wiki/` 链接时：

1. 加载并遵循 `lark-doc` Skill，包括 `lark-shared` 认证规则以及文档、媒体读取
   规则。
2. 使用以下命令读取文档：

   ```bash
   lark-cli docs +fetch --as user --doc "<URL>"
   ```

3. `/wiki/` 链接可直接作为文档来源，不能只读取 Wiki 容器后停止。
4. 必须覆盖完整文档。对于大型文档，应使用目录和分段读取，直到覆盖所有相关章节
   和媒体块。
5. 保持文档原始顺序，将每个 `<img>` 与距离最近的标题、说明、指令或表格单元格
   关联。
6. 必须逐张查看参考图。优先直接使用 `<img>` 中可访问的图片 URL；否则使用
   `+media-preview` 获取预览。仅在用户明确要求下载或来源为画板时使用
   `+media-download`。

如果 CLI 不可用、认证或权限失败、媒体无法读取，不得根据不完整文本继续生成并声称
已完整读取。应先走 `lark-shared` 授权恢复；仍不可用时，可使用已有登录状态的 Chrome
完整查看文档。两条路径均无法获得完整资料时，必须在生成前停止，并请用户授权、导出
文档或补充缺失图片。

### 2.2 每个模板的内部索引

每张参考图建立一条内部记录，至少包含：

- 模板编号和简短场景名；
- 明确要求的模特地区和性别；
- 根据主题推断的非名人模特气质、造型、表情和日常情境；
- 构图、姿势、服装、道具、环境、光线、色彩和镜头信息；
- 应忽略的截图界面元素；
- 来源歧义或缺失信息。

地区有明确要求时必须遵循；没有要求时默认使用欧美模特。

模特气质应根据参考图主题、场景、造型、情绪和目标受众推断。应选择可信的日常人物，
不能默认套用秀场模特或明星脸。

手机截图或平台截图只作为参考图容器。分析时只关注主视觉，排除状态栏、按钮、用户
名、缩略图、说明文字、箭头、来源标记、Logo 和水印。

## 3. 阶段二：生成 Soul 模特人物素材

### 3.1 固定模型设置

通过当前画布模型目录解析 `soul-v2-standard` 及其 Provider。每个 Soul 节点必须
显式设置：

- 比例：`1:1`；
- 分辨率/质量：`720p`；
- 风格：当前模型目录 `style_options` 中名为 `General` 的选项；
- 提示词增强：关闭，即 `soulEnhancePrompt: false`；
- 输出数量：`1`，除非用户明确要求批量候选。

不能依赖节点默认值。执行前必须把 Provider、模型和目录支持的参数值保存到节点。

### 3.2 模特人物要求

每个模板分别生成一张人物素材，要求：

- 根据主题推断甜美、冷酷、成熟自信、帅气、活泼、优雅或其他合适气质；
- 只推断宽泛穿搭方向，例如甜美休闲、冷酷街头、优雅极简或放松日常；
- 成年人，高颜值，但仍具有可信的 Instagram/TikTok 日常时尚博主感；
- 是一张独立的、类似 Pinterest 人物素材的照片；
- 使用新设计的简洁日常穿搭；
- 具有自然皮肤和生活化背景的真实手机随拍感；
- 不能做成商业大片、杂志大片或电影宣传照；
- 正面面对镜头，脸部和主要五官清楚，无严重遮挡；
- 表情和肢体语言符合所推断的气质。

地区、明确性别和推断气质只用于 Soul 模特提示词，不得把固定身份特征带入后续可复用
模板效果提示词。

### 3.3 Soul 提示词规则

Soul 模特提示词保持使用中文，并且只写正向视觉描述。

参考结构：

```text
成年[地区和明确要求的性别]，[根据模板主题推断的甜美、冷酷、御姐、帅气或其他气质]，
真实的 Instagram/TikTok 高颜值时尚博主风格，五官精致自然，穿着符合[甜美休闲、
冷酷街头、优雅极简或其他宽泛风格]的简洁日常时尚穿搭，正面面对镜头，脸部与主要
五官清晰可见，自然皮肤质感，简单日常背景，自然光，真实手机随拍质感，像在
Pinterest 上找到的独立博主人物素材照片。
```

禁止添加：

- 负向提示词；
- 排除项列表；
- 以禁止语气开头的句子；
- “地区：”“模型：”“要求：”等元数据标签。

Soul 阶段只把参考模板当作选角简报，不能复制参考图中的具体服装款式、颜色组合、
饰品、姿势、道具、构图或场景。这些信息只用于后续模板效果提示词。

### 3.4 Soul 结果验收与临时资产规则

Soul 人物图唯一的视觉可用性标准是：脸部清楚且没有严重遮挡。

满足该标准即接受，不增加其他视觉质量淘汰条件。偶发水印不是重新生成理由。

接受的 Soul 结果及临时 URL 不得转换成持久化私有画布资产。应保留原生成节点，并把
其图片输出直接连接到下游图像编辑节点。在临时结果有效期间完成付费样片。

如果临时结果在后续执行前过期，应使用不变的提示词、种子和设置重新执行 Soul 节点，
不能通过上传或持久化方式绕过临时结果规则。

## 4. 阶段三：反向整理可复用模板效果提示词

### 4.1 分析范围

只描述参考图中的主画面，不描述截图容器。需要捕捉：

- 构图、裁切和主体比例；
- 动作、姿势、视线和人物关系；
- 服装、饰品和道具；
- 场景和空间关系；
- 光线方向、明暗、色彩结构和氛围；
- 镜头角度、透视和景深；
- 材质、纹理和摄影处理。

### 4.2 身份中立

模板效果提示词必须保持身份中立，不能固定：

- 性别；
- 年龄；
- 肤色；
- 五官特征；
- 脸型；
- 发型；
- 体型。

统一使用 “the person in the uploaded image” 或等价的中性表达指代输入人物。

当服装或姿势属于模板视觉效果本身时，可以明确描述；但不能把输入人物的固定身份特征
写死在模板里。

### 4.3 正式英文提示词标准

可复用模板效果提示词必须使用正式、可直接投入生产的英文自然语言。

提示词必须在只有当前输入图片的情况下独立成立，并完整说明：

1. 上传图片提供需要保持可识别身份的人物；
2. 目标构图、姿势、视线、服装、道具、环境和空间关系；
3. 光线、色彩、镜头角度、景深、材质、纹理和最终摄影质感；
4. 必要时，用简洁自然的英文句子排除截图界面、意外文字、多余人物或严重肢体错误。

推荐的自然语言组织方式：

1. 先说明生成目标和身份来源。例如：

   > Generate a photorealistic portrait based on the person in the uploaded
   > image, preserving the person’s recognizable identity and natural facial
   > structure.

2. 用完整段落描述全部视觉要求。
3. 必要时以简洁质量约束结尾。例如：

   > Keep the face clearly readable and the anatomy plausible. The final image
   > must not contain screenshot interfaces, random text, logos, watermarks,
   > extra people, or duplicated body parts.

### 4.4 提示词正文禁止项

提示词正文中不得出现任何提示词工程字段名或分区标签，包括但不限于：

- `CHANGE`；
- `PRESERVE`；
- `REFERENCE ROLE`；
- `PROHIBIT`；
- `NEGATIVE PROMPT`；
- 其他类似的表单、Schema 或元数据字段。

提示词正文也不得包含：

- 项目符号式检查清单；
- 分析笔记；
- 参考图对比结论；
- QA 结论；
- 修改记录；
- 工作流状态；
- 版本迭代历史。

文本节点只能保存可直接送入模型的最终提示词，并通过文本输入 Handle 连接到生成节点。

### 4.5 独立生成原则

每次模型调用都是独立的。提示词必须只依赖当前输入图片，不能依赖：

- 对话历史；
- 上一个提示词；
- 上一张生成图；
- 未明确写出的“已成功效果”。

提示词中禁止出现以下过程依赖话术：

- `V1`、`V2`；
- “the previous version”；
- “the earlier result”；
- “the first generation”；
- “preserve what already works”；
- “keep the successful black-and-white look”；
- “continue the atmosphere established earlier”；
- 任何要求继承、延续、细化或改善上一张结果中未明确描述属性的话术。

版本标记只允许出现在节点命名和工作流报告中，不能进入提示词正文。

例如，不应写：

> Preserve V1’s successful high-contrast black-and-white texture and dark
> background.

应直接写成当前调用可以独立执行的视觉要求：

> Use high-contrast black-and-white photography, a deep charcoal studio
> background, realistic skin texture, and precise focus on both eyes and the
> lips.

## 5. 阶段四：生成付费样片

### 5.1 模型选择

每个模板生成一张 `2:3` 付费样片。

从当前模型目录解析准确的 Provider 和模型：

1. 默认使用 fal.ai `openai/gpt-image-2`。
2. 当任务明显依赖多张参考图、复杂合成或更强的跨图一致性时，优先使用 fal.ai
   `fal-ai/nano-banana-pro`。
3. 除非用户明确要求对比，或者首选模型失败或明显偏离模板，否则不能同时运行两个
   付费模型。

输出比例必须为 `2:3`，使用当前运行时模型目录提供的准确尺寸参数。

付费模型直接使用已接受的 Soul 结果和可复用效果提示词。保持 Soul 人物身份，同时
实现参考图构图。节点和分组名称必须包含模板编号、阶段、模型和 `2:3`。

### 5.2 样片检查维度

每张样片都要与主参考图并排比较。忽略截图外壳，检查：

1. 构图、裁切、主体比例和相机角度；
2. 姿势、视线、动作以及人物与环境的关系；
3. 服装、道具和标志性场景元素；
4. 前景、背景、空间布局和景深；
5. 光线方向、明暗对比、色彩结构和氛围；
6. 镜头感、材质、摄影处理和整体情绪；
7. 多余 UI、随机文字、肢体错误和严重面部遮挡；
8. Soul 人物身份是否保持；
9. 面部是否清晰，手部和整体解剖是否合理。

### 5.3 判定

**达到或超过要求**

当标志性构图、人物关系、场景、造型、光线、色彩和氛围都存在，并且没有关键缺陷时：

- 保留 V1；
- 不生成新的付费版本。

**需要修正**

当一个或多个重要视觉关系缺失、方向错误、构图不当、表现较弱或互相矛盾时：

1. 在提示词之外记录影响最大的 1 至 3 个问题。
2. 更新相应视觉指令。
3. 使用同一个付费模型和同一个已接受 Soul 结果生成一次 V2。
4. 保留 V1，不覆盖原结果。

### 5.4 V2 提示词规则

V2 节点和结果可以使用 `V2` 标签，但 V2 提示词正文中不能出现 `V1`、`V2` 或任何
上一版结果引用。

V2 提示词必须是完整、独立的英文提示词，并且：

- 明确修正识别出的关键问题；
- 重新完整描述目标构图和身份保持方式；
- 对 V1 中已经正确的视觉要求，也必须重新明确写出；
- 不能使用“保留上一版成功效果”等增量指令；
- 使用相同的 Soul 结果、付费模型和 `2:3` 输出；
- 另建提示词节点和结果节点，不覆盖 V1。

V2 完成后再次与参考图比较。自动付费修正最多一次。如果 V2 仍未达到要求，报告剩余
问题并交由用户判断，不能进入无限付费重试。

技术失败可以单独重试，但不能静默替换已经做出的模型选择。

## 6. 阶段五：暂停并等待用户验收

所有付费样片进入最终状态后：

1. 整理并聚焦付费样片分组。
2. 报告每个模板使用的模型和参考图对比结论。
3. 说明保留 V1，还是生成了提示词修正版 V2。
4. 展示最终候选结果。
5. 停止执行。

用户明确说出“验收通过”“可以生成免费版”或同等含义之前，不得创建、配置或运行
Free/boogui2i 节点。

如果用户拒绝部分样片，只修改被拒绝的提示词或结果，重新展示后继续停留在验收门禁。

## 7. 阶段六：验收后生成免费对照版本

收到明确验收后：

1. 读取当前画布，识别已批准的模板分组。
2. 从实时模型目录解析 Provider `Free`、模型 ID `ggnnp`、显示名
   `boogui2i`。
3. 为每个已批准模板创建独立的 `2:3` 免费版节点。
4. 使用同一个已接受 Soul 结果，以及完全相同的已批准 V1 或 V2 提示词，保证公平
   对比。
5. 如果 Soul 临时结果过期，使用原提示词、种子和设置重新执行 Soul，不得持久化。
6. 不覆盖付费样片。
7. 运行并检查免费节点，把付费版和免费版排列成便于对比的布局。

除非用户明确要求直接复刻付费图，否则不能把付费结果本身作为额外参考图。

## 8. 画布结构

每个模板采用以下逻辑顺序：

```text
模特提示词 → Soul 2.0 临时结果 → 可复用效果提示词
                                     → 付费 2:3 样片
                                     → 用户验收门禁
                                     → boogui2i 2:3 对照版本
```

每个模板放在清晰命名的分组中。保留画布中无关内容。添加新模型版本时，不能覆盖已接受
的结果。

## 9. 完成报告

每个已完成阶段必须报告：

- 已处理模板及使用的地区默认值；
- 每个参考主题推断的模特气质及理由；
- 准确的 Provider/模型、比例、Soul 质量和风格、提示词增强状态；
- 成功、失败或重新生成的项目；
- 参考图对比结论、主要差异和 V2 提示词修正；
- 当前是在等待验收，还是已经生成免费对照；
- 仍存在的视觉限制。
